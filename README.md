# MH Wilds OCR — Step 1.25-C v4.5.3

## 目的
v4.5.2の実機ログで確認された「19スロットがすべて1番スロット表示になる」「DB候補が刺撃珠に偏る」問題を、OCR画像処理を大きく変更せずに修正。

## v4.5.3変更点
- 装飾品グループを8グループ固定モデルへ整理。
- サブ武器を固定グループとして挿入しないため、以降の装備グループ番号がずれない。
- `groupIndex` / `slotInGroup` を同一ROIオブジェクトへ保持し、`result.rois` と `groups[].slots` のID消失を防止。
- OCR対象ROIを `groups[].slots` から再構成し、1番スロット固定化を防止。
- 装飾品DB照合を「slot + kind」のハード条件に加え、「珠」までの名前核を最優先に変更。
- 核が完全一致するDB候補がある場合は、その候補群だけで照合。
- 核が一致しない場合は類似度0.62未満を候補なしとして扱い、刺撃珠のような無関係候補を表示しにくくした。
- OCR Lvと装備DB期待Lvが異なる場合に明示表示。
- 内部構造セルフテスト関数 `selfTestDecorationStructureV453()` を追加。
- 装備OCRの画像処理・ROIロジックは原則v4.5.2から変更していない。

## 内部シミュレーション結果
想定 8グループ / 19スロットを以下で検証：
`[3,3,3,2,2,2,2,2]`

- グループ数: 8 → PASS
- スロット数: 19 → PASS
- 各グループ最大3スロット → PASS
- `groupIndex:slotInGroup` の重複なし → PASS
- 攻撃珠II、超心珠、達人珠、業物・匠珠などの名前核一致 → 正しいDB候補へ寄ることを確認
- 澤身→渾身のような1文字OCR誤り → 類似核で候補化
- 無関係な刺撃珠 → 名前核一致候補が存在する場合は候補群から排除

## 注意
この内部シミュレーションは実ブラウザ上のTesseract実行そのものではありません。実画像からのOCR文字列生成は次の実機確認で検証します。
