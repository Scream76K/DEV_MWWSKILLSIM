# MH Wilds OCR — Step 1.25-B v2.4

## 目的
Step 1.25-A v6 で自動検出した装備9領域から、メイン武器・5防具・護石の装備名を個別OCRし、部位限定DB候補を提示する。

- メイン武器：武器DBのみ
- 頭・胴・腕・腰・脚：MHDB防具DBを部位（kind）で限定
- 護石：MHDB護石DB（ranks内の名称）
- サブ武器：検出対象だがシミュレーター反映対象外
- 装衣：検出対象だがシミュレーター反映対象外
- この段階ではシミュレーター本体へ自動適用しない

## Step 1.25-A v6からの引き継ぎ
装備ピッチは固定値を使わず、画面内のOCRアンカーから推定された値を利用する。解像度・表示倍率が違うスクリーンショットでも各カード領域を生成できる。

## Step 1.25-B v2.4 の認識フロー
1. 画面構造検出
2. 9領域生成
3. 画面内のラベル位置・装備ピッチから「装備名1行」だけを自動切り出し
4. 切り出した1行をPSM7でOCR（背景・アイコン・区切り線の混入を抑制）
5. OCR結果から既知のUIラベルを除去
6. 対応部位のDBだけで候補検索
7. 上位候補を複数保持
8. 文字評価・OCR信頼度・複数OCR支持を統合
9. 自動確定候補／ユーザー確認／候補選択／手動入力を表示

## DB
MHDB Wilds APIの日本語エンドポイントを使用する。防具は `/ja/armor`、護石は `/ja/charms`。護石名はトップレベルではなく `ranks[].name` を使用するため、ranksを取得するAPI projectionを明示している。

## v2.1の変更点
従来は装備カード全体に近い領域をOCRしていたため、背景・アイコン・UIラベルが混入し、今回の実画像では装備名の認識率が低下した。v2では、構造検出で得たラベル位置と自動推定ピッチを使って、ラベル直下の装備名1行を比率ベースで切り出す。固定pxのY座標は使用しない。

## 処理時間対策
各装備につき最大3種類の前処理を使用するが、2回目までで高信頼・候補差が十分な場合は3回目を省略する早期終了を入れている。

## v2.1 変更点
- 装備名OCRの前処理を `白文字強調 / 白背景反転 / グレースケール` に変更。
- 旧 `threshold155` の強い二値化は装備名OCRから除外。
- 装備名クロップの拡大率を4倍から2.5倍へ変更し、補間品質をmediumに変更。
- OCR入力前に横30px・縦20px相当の明示的パディングを追加。
- 構造検出、部位限定DB、候補統合、サブ武器/装衣の除外方針は変更しない。


## Step 1.25-B v2.2 の変更点
- 防具名末尾の α / β / γ を本体名とは分離して評価。
- `v/V/ν`、`a/aq`、`b/bq` など、装備名末尾に限定したOCR誤認識を吸収。
- 明示的なサブタイプ一致は加点、不一致は減点するが、サブタイプ不明時は通常の文字評価を維持。
- 武器・護石にはα/β/γの特別扱いを行わない（DB候補の通常文字評価のみ）。
- Step 1.25-B v2.1 のOCR前処理・自動レイアウト・DB候補集約は維持。


## Step 1.25-B v2.3.1 の変更点
- 防具OCRを「シリーズ認識 → α/β/γ認識」の2段階構造へ変更。
- 第1段階ではα/β/γを無視してシリーズ本体だけを比較する。
- シリーズ候補を絞り込んだ後、そのシリーズに属する型式だけでα/β/γを判定する。
- `v/V/ν`、`a/aq`、`b/bq/BQ` などの末尾OCR誤認識は第2段階で処理する。
- 武器・護石の認識方式は変更しない。
- OCR前処理、画像レイアウト自動検出、サブ武器/装衣の反映対象外方針は維持。
- 防具結果にはシリーズ評価と型式評価を分離して表示する。


## v2.4 追加設計
- 防具は「シリーズ認識 → α/β/γ型式認識」の2段階。
- シリーズ認識では型式記号を無視し、OCRの挿入・欠落に耐える編集距離/LCSベースの類似度を使用。
- 部位ごとにDBを限定し、別部位の装備名を候補に混ぜない。
- 型式はシリーズ確定後、末尾だけを局所解析する。全体文字列への無条件置換は行わない。
- OCR前処理は白文字強調・Otsu・グレースケールの3パス。特定の背景色や昼夜条件に固定しない。
- Otsuは画像ごとの輝度分布から閾値を決めるため、背景の明暗・色変化への耐性を狙う。
- 既存の処理時間を維持するため、3パスを上限とし、十分な証拠が揃った場合は早期終了する。
- 自動確定はスコアだけでなく、シリーズ確度・型式一致・OCR信頼度・支持数・候補差を組み合わせる。
- 武器と護石の既存認識フローは原則維持。

## v2.4 の自動確定方針
「閾値を下げて無理に確定」ではなく、部位限定DBとシリーズ階層化で正しい候補を上位に持ち上げ、複数の証拠が揃った場合のみ自動確定する。
