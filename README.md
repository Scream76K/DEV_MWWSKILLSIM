# MH Wilds OCR — Step 1.25-B v3.1.1 Crop Spike

Monster Hunter Wilds の装備変更画面を対象に、OCRへ渡す画像を環境変動に強くするOCR前処理へ進む前に、装備名の切り出し境界だけを検証する開発版です。

## v3.1.1 Crop Spike 変更点

- 本版ではOCRを実行せず、装備名クロップの境界だけを比較検証する。
- 白文字強調・HSV白文字抽出・グレースケールを標準OCRパスとして維持。
- 局所コントラスト＋軽いアンシャープ処理は比較用に残し、本番標準パスからは採用判断を保留。
- Otsuは本番では救済用のまま維持し、Spikeでは比較対象として明示的に実行。
- Spike専用にソフト白文字抽出を追加。アンチエイリアスを残した連続輝度マスクを比較する。
- OCR末尾ノイズ（`BQ 央`、`v 一`、`aq 一`など）を専用テール抽出で処理。
- 既存のシリーズ先行・DB候補統合・メイン武器のみ反映・サブ武器除外の方針は維持。
- 標準パスで高信頼候補が得られた場合は救済OCRを実行しない。

## v3.1.1 の検証対象

- 現在方式
- 広幅（長い装備名の末尾切れを確認）
- 広幅＋左右上下余白
- 広幅＋余白多め（上下方向の文字切れを確認）

7部位について4種類の切り出し画像を表示し、OCRは実行しません。
切り出し境界を確定した後、前処理Spikeへ戻ります。

## 処理フロー

```text
実スクショ
 ↓
画面構造を自動検出
 ↓
装備名領域を余白付きで切り出し
 ↓
動的リサイズ（目標文字高さ 約40px）
 ↓
標準OCR
 ├─ 白文字強調
 ├─ HSV白文字抽出
 ├─ グレースケール
 └─ 局所コントラスト
 ↓
シリーズ/DB候補統合
 ↓
防具のみ：末尾 α/β/γ 専用OCR
 ↓
必要時のみ Otsu 救済OCR
 ↓
自動確定 / ユーザー確認 / 候補選択 / 手動入力
```

## 開発手順

```text
実スクショ
 ↓
前処理画像の確認
 ↓
こちらの環境で静的・回帰テスト
 ↓
ユーザー環境で実OCR
 ↓
結果比較
 ↓
次の変更を1つずつ判断
```

処理時間を重要な制約として扱い、標準パスの早期終了と救済パスの条件付き実行を維持します。

## Spikeの目的

v3.1は本番ロジックを変更せず、実スクリーンショット上で以下を比較するための検証版です。

- ソフト白文字抽出
- グレースケール
- CLAHE比較
- Otsu救済比較

各方式について7部位のraw OCR、Confidence、処理時間を記録します。比較結果を基に、次版で本番標準パスを変更するか判断します。
