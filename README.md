# MH Wilds OCR v4.4.8

## 今回の目的
装飾品を「24個の独立スロット」として扱う設計から、
**装備グループ × 1～3スロット**へ移行する。

## v4.4.8 の変更点
- 装飾品画面の最大24行ROIは維持するが、空の区切り行をスロットとして扱わない。
- 区切り行を画像テクスチャから検出し、連続ブロックを作る。
- 1グループ最大3スロットとして論理グループへ再構成。
- 区切りのない先頭ブロックなど、3スロットを超えるブロックは3件単位で安全に分割。
- 表示上の装備グループは最大9件（メイン武器、サブ武器、頭、胴、腕、腰、脚、護石、装衣）を想定。
- サブ武器グループは検出・保持するが、ビルド反映対象から除外。
- 装備OCR結果に `slots / decorationSlots / slotLevels` が存在する場合は保持し、装飾品グループの期待スロットLvとして照合できる構造に変更。
- 装備解析と装飾品解析は順不同。後から装備解析した場合でもグループのDBスロット情報を再評価する。
- 装飾品OCRは区切り行をOCRせず、実際の装着行だけを処理。
- OCR文字列から `[1]～[3]` を抽出し、各スロットの `slotLevel` として保持。
- ビルド反映データには「表示グループ」と「ビルド反映対象グループ」を分離して保持。

## 実画像内部検証
同梱の `decoration_reference_IMG_9323_1.jpeg` を基準に、24行境界→区切り行→グループ再構成を検証。

検証結果：
- 25境界を検出
- 区切り行：5本
- 連続ブロック：`8, 2, 2, 2, 2, 3`
- 1グループ最大3件で再構成：`3, 3, 2, 2, 2, 2, 2, 3`
- 合計8グループ / 19装着スロット
- 1グループ3件超の論理グループは生成しない

## サイズ適応内部検証
同一参照画像を16:9ゲーム領域へ配置して以下のサイズを確認：
- 1536×864
- 1920×1080
- 2560×1440
- 3840×2160
- 2560×1080
- 3440×1440
- 1080×1920
- 706×1536

8サイズすべてで同じグループ構成 `3,3,2,2,2,2,2,3` を確認。

## 安全側の挙動
- 25境界が成立しない場合、24行ROIを確定しない。
- グループ数が表示上限を超えた場合、グループを確定しない。
- 1グループが4スロット以上にならないよう分割する。
- サブ武器は解析結果として保持してもビルド反映対象にはしない。
