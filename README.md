# MH Wilds OCR — Step 1.25-B v2.1

## 目的
Step 1.25-A v6 で自動検出した装備9領域から、メイン武器・5防具・護石の装備名を個別OCRし、部位限定DB候補を提示する。

- メイン武器：武器DBのみ
- 頭・胴・腕・腰・脚：MHDB防具DBを部位（kind）で限定
- 護石：MHDB護石DB（ranks内の名称）
- サブ武器：検出対象だがシミュレーター反映対象外
- 装衣：検出対象だがシミュレーター反映対象外
- この段階ではシミュレーター本体へ自動適用しない

## Step 1.25-A v6からの引き継ぎ
装備ピッチは固定値を使わず、画面内のOCRアンカーから推定された値を利用する。解像度・表示倍率が違うスクリーンショットでも各カード領域を生成できる。

## Step 1.25-B v2.1 の認識フロー
1. 画面構造検出
2. 9領域生成
3. 画面内のラベル位置・装備ピッチから「装備名1行」だけを自動切り出し
4. 切り出した1行をPSM7でOCR（背景・アイコン・区切り線の混入を抑制）
5. OCR結果から既知のUIラベルを除去
6. 対応部位のDBだけで候補検索
7. 上位候補を複数保持
8. 文字評価・OCR信頼度・複数OCR支持を統合
9. 自動確定候補／ユーザー確認／候補選択／手動入力を表示

## DB
MHDB Wilds APIの日本語エンドポイントを使用する。防具は `/ja/armor`、護石は `/ja/charms`。護石名はトップレベルではなく `ranks[].name` を使用するため、ranksを取得するAPI projectionを明示している。

## v2.1の変更点
従来は装備カード全体に近い領域をOCRしていたため、背景・アイコン・UIラベルが混入し、今回の実画像では装備名の認識率が低下した。v2では、構造検出で得たラベル位置と自動推定ピッチを使って、ラベル直下の装備名1行を比率ベースで切り出す。固定pxのY座標は使用しない。

## 処理時間対策
各装備につき最大3種類の前処理を使用するが、2回目までで高信頼・候補差が十分な場合は3回目を省略する早期終了を入れている。

- Step 1.25-A 回帰テスト

- 候補集約

## 注意
まだ装飾品・スキルの認識、装備への自動適用、シミュレーター本体接続は行わない。


## v2.1 変更点
- 装備名OCRの前処理を `白文字強調 / 白背景反転 / グレースケール` に変更。
- 旧 `threshold155` の強い二値化は装備名OCRから除外。
- 装備名クロップの拡大率を4倍から2.5倍へ変更し、補間品質をmediumに変更。
- OCR入力前に横30px・縦20px相当の明示的パディングを追加。
- 構造検出、部位限定DB、候補統合、サブ武器/装衣の除外方針は変更しない。
