# MH Wilds OCR — Step 1.25-C v4.0.6

DBアイコンアンカー方式を維持し、OCR領域だけを過去の実績方式へ回帰するA/B切り分け版。

## v4.0.6の目的

v4.0.5で発生していたOCR精度低下について、変数を1つに絞って検証する。

### 新しい部分
- DBアイコンテンプレート照合
- 3アンカー（メイン・頭・胴）による9行グリッド生成
- 上段ピッチ／防具ピッチによる行位置復元

### 回帰する部分
装備名OCR領域は、過去のアイコンアンカー方式へ戻す。

- X = `icon.x + icon.width + 8`
- Y = `icon.y + icon.height × 0.08`
- H = `icon.height × 0.76`
- W = `icon.width × 7`
- 画像外には `clampRectToImage()` でクリップ

v4.0.4/v4.0.5で追加した「アイコン右下を中心とした58%帯」および「スロット列からOCR右端を推定する方式」は、この回帰テストでは使用しない。

## OCR前処理

本番OCRの前処理アルゴリズムは変更しない。

標準：
1. 白文字強調
2. 白文字・色除去（HSV）
3. グレースケール

救済：
4. 局所コントラスト＋軽いシャープ
5. Otsu

救済2方式は標準3方式で十分な候補が得られなかった場合だけ本番OCRで使用する。

## v4.0.6で追加した確認

「OCR前処理を確認」では、OCR実行前に以下を目視確認できる。

- 旧アイコンアンカー式の切り出し領域
- 標準3方式＋救済2方式の5種類の前処理画像

これにより、
「切り出し範囲の問題」なのか「前処理画像の問題」なのかを分離して確認できる。

## sample_game.pngで期待される旧式OCR領域

アンカーが以下の場合：

- メイン: `(26,111) 45×45`
- 頭: `(26,243) 45×45`
- 胴: `(26,318) 45×45`

メインの旧式OCR領域は概ね：

- `(79,115) 315×34`

となる。

行ごとに同じ式で生成される。

## 比較のルール

v4.0.6では、OCR精度を上げるための新しい前処理を追加しない。

1. DBアイコン検出
2. 9行生成
3. 旧OCR領域を生成
4. 前処理5方式を確認
5. Tesseract PSM7
6. DB候補統合

この順で確認し、v4.0.5との差分をOCR領域に限定する。
