# ファイル所有権・統合順序

所有権は運用上のロックであり、OSの強制権限ではない。ロックはTASKS.mdに task/担当/許可パス/基準ハッシュ/取得時点/返却状態を記録。初回6調査は書き込みロックを取得しない。

| 対象 | 変更担当 | 必須レビュー |
|---|---|---|
| index.html（全体・CSS・埋め込みDB/OCR含む） | himmelのみ | 変更領域の担当 + fern + eisen。DBはheiter、仕様はユーザー |
| 独立した計算モジュールと計算回帰 | frieren（指定パスのみ） | fern、eisen、根拠はheiter |
| CSS/表示専用モジュールと表示回帰 | stark（指定パスのみ） | fern、出力契約はfrieren |
| 正式DB/MHDB取得・保存/Technique DB/テンプレート正本 | 原則直接変更禁止。heiterは根拠付き案 | heiter + frieren + fern + ユーザー判断が必要な仕様 |
| テスト・検証補助 | fern（指定パスのみ） | 期待値に関わる担当、himmel |
| 仕様・依存図・境界レビュー | eisen | 関連担当、仕様変更はユーザー |
| 独立OCRコード/回帰 | sein（指定パスのみ） | fern + heiter（照合） + eisen（座標境界） |
| 組織設定・タスク台帳・統合報告 | himmel | 各担当の役割確認 |

統合順序：heiterの根拠監査 → eisenの境界/影響確認 → 必要なユーザー仕様承認 → frieren計算 → sein独立OCR → stark表示 → fern回帰 → himmel最終照合。依存しないファイルの調査は並行可能。これはGit merge実行指示ではなく、承認済み変更案を取り込む審査順序。

共有index.htmlの複数担当同時編集、別タスクの変更の上書き、期待値だけを合わせる統合を禁止。担当が意図しない差分を見つけたら触らず報告する。
