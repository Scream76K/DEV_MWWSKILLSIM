# r64 モバイル比較表示と参考計算の配置修正

## ユーザー確認

r63で武器切り替え、OCR反映、参考計算の基本表示はユーザーがOKと確認。IMG_9675/9676で笛参考欄がタイトル前にあること、装備比較後のページ縮小を報告。

## 原因と変更

1. 参考計算欄をheader前へ挿入していた。タイトル下の技DB確認欄の後へ移動。入力値・計算API・イベントは変更しない。
2. 比較表は最小680pxで横スクロール用のラッパーがあったが、外側のグリッド列の最小サイズが内容幅に依存していた。比較結果を挿入するとグリッド自体が広がり、モバイルレイアウトのビューポートが拡大して全体が縮小表示された。

Chromiumの390px幅で、保存3件→全選択→比較を操作すると、修正前はinnerWidth/文書幅が約745pxに広がった。320pxでは744pxを確認。修正ではグリッドの可変列をminmax(0,1fr)、直接の子をmin-width:0とし、比較ラッパーを最大100%幅に制限。表の680px幅は残し、横スクロールをパネル内に限定した。ページ全体をoverflow:hiddenで隠す修正は行わない。

## 検証

- 既存単体/回帰92件成功。
- ページ全体DOM統合3件成功。
- 実Chromiumのレイアウト回帰1件成功（320/390/430/768/1280pxの5条件）。

修正後の文書幅とinnerWidthは各指定幅と一致。スマホの比較表680pxはパネル内スクロールを維持。保存・比較の実ボタンを操作し、結果の7行とJavaScriptエラーなしを確認。配置チェックはheaderが参考欄より先にあることを検証。

ブラウザテストは公式データをダウンロードせず、空の武器索引を明示的に初期化したレイアウト用保存セットを使用。装備の実火力の検証ではない。Chromiumによる検証であり、iPhone Safari実機の再確認は未実施。環境に日本語フォントがなく、見た目・文字幅の完全一致までは主張しない。

## 再現

Node24.13以上でnpm ci、npm test、npm run test:dom。ブラウザを準備してnpm run test:browser。通常はnpx playwright install chromiumで準備する。既存実行ファイルを使う場合はCHROMIUM_EXECUTABLEに絶対パスを指定可能。PLAYWRIGHT_MODULE_PATHで既存モジュールのパスも指定可能。ブラウザ本体・node_modulesは配布ZIPに含めない。

装備・OCR・ゲームデータ・MV・属性補正・計算保留条件は変更しない。
